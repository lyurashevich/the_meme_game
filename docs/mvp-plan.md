# План MVP

## Принятые решения

- Все игровые действия идут через WebSocket. REST остаётся только для чтения и health-check.
- Фронтенд на React (Vite + TypeScript + Tailwind). Существующий Vue-макет (`frontend/`) портируется на React: вёрстку и компоненты сохраняем, переписываем на React и подключаем к бэкенду.
- Запускаемся на одном инстансе. Состояние хранится в памяти, но доступ к нему идёт через интерфейс репозитория, чтобы потом подключить Redis заменой реализации.
- Картинки мемов лежат в S3-совместимом хранилище: локально MinIO, в проде S3. В БД хранится ключ объекта, а публичный URL собирается из `MEDIA_BASE_URL`.
- В MVP входят чат и настройки игры. Приватные комнаты и вход в идущую игру не входят: вход во время игры запрещён.

## WS-протокол

Подключение: `GET /ws?reconnect_token=<токен>`. Если токена нет или он невалиден, создаётся новый игрок.

### Клиент → сервер

Формат: `{"event": "...", "request_id": "<uuid>", "payload": {...}}`.

| event | payload | кто может |
|---|---|---|
| `update_profile` | `{username?, avatar_id?}` (ник 1–32 символа; в комнате — уникальный) | любой |
| `create_room` | `{name?, max_players}` (3–10, по умолчанию 10) | игрок не в комнате |
| `join_room` | `{room_id}` | игрок не в комнате; комната не полная, игра не идёт, ник уникален |
| `leave_room` | `{confirm}` | игрок в комнате |
| `update_settings` | `{round_time_limit, max_rounds?, score_to_win?}` | владелец, игра не идёт (`game_already_started`) |
| `start_game` | `{}` | владелец, игроков ≥ 3 |
| `end_game` | `{}` | владелец |
| `select_card` | `{card_id}` | не ведущий, фаза `choosing_cards` |
| `choose_winner` | `{card_id}` | ведущий, фаза `leader_choosing` |
| `chat_message` | `{text}` (1–500 символов) | игрок в комнате; не больше 5 сообщений за 10 с, иначе `too_many_messages` |

На каждое действие сервер отвечает одним из двух сообщений:
- `{"event": "ack", "request_id": ..., "payload": {...}}`
- `{"event": "error", "request_id": ..., "payload": {"code": ..., "message": ...}}`

Например, `leave_room` без `confirm` возвращает в ack `{requires_confirmation: true}`.

### Сервер → клиент

Основная модель — персональный снапшот. После любого изменения в комнате каждому игроку уходит его `room_state` целиком: при ≤10 игроках это дёшево. Клиенту не нужно склеивать дельты, реконнект работает так же.

- `session` — `{player_id, reconnect_token, username, avatar_id}`. Отправляется при подключении. Затем приходит `room_state` (если игрок в комнате, с историей чата) или `rooms_list`.
- `rooms_list` — список публичных комнат: `[{id, name, owner_name, players_count, max_players, round_time_limit, max_rounds, status: "waiting" | "playing"}]`, `max_rounds: null` — без лимита. Отправляется игрокам вне комнат при любом изменении списка.
- `room_state` — снапшот:
  ```
  {
    server_time,                          // ISO-время сервера в момент отправки
    room: {id, name, owner_id, max_players, settings: {round_time_limit, max_rounds, score_to_win}},
    players: [{id, username, avatar_id, score, is_connected}],
    game: null | {                        // null — лобби (игры нет или она закончилась)
      state, round_number, round_state, leader_id, situation: {id, text},
      my_hand: [{id, image_url}],
      my_selected_card_id,
      submitted_player_ids: [...],        // кто уже сдал карту (без картинок)
      table: [{id, image_url}],           // с фазы leader_choosing: анонимно, по возрастанию id
      winner: null | {player_id, card_id},
      ends_at                             // ISO-дедлайн текущей фазы; null, пока показывается победитель
    },
    chat: [{player_id, username, text, timestamp}]   // только после входа в комнату или реконнекта
  }
  ```
  Таймер на клиенте: `осталось = ends_at − server_time` в момент получения, дальше отсчёт по локальным часам. Так расхождение часов клиента и сервера не влияет на таймер.

  Фазы раунда: `choosing_cards` (игроки сдают карты, `round_time_limit` секунд) → `leader_choosing` (ведущий выбирает, 30 секунд). Когда ведущий выбрал, фаза остаётся `leader_choosing`, но заполняется `winner`, а `ends_at` становится `null`: пару секунд показывается победитель, потом начинается следующий раунд. Если время на сдачу вышло и никто не сдал карту, начинается следующий раунд. Если ведущий не успел, раунд заканчивается без победителя.

  Отключение игрока: остальные видят `is_connected: false`; на возвращение (по `reconnect_token`) даётся 60 секунд, после чего игрок выходит из комнаты так же, как если бы вышел сам. Отключившегося ведущего не заменяют досрочно: раунд ждёт его 30 секунд и заканчивается без победителя, а если он не вернулся за 60 секунд и раунд ещё идёт — раунд прерывается и начинается новый со следующим ведущим. Сданные карты прерванного раунда уходят в сброс.
- `round_winner` — `{winner_id, card_id}`. Разовое событие для анимации; приходит до снапшота следующего раунда.
- `game_ended` — `{room_id, reason, final_scores, winner_ids}`, `reason`: `owner_ended` | `limit_reached` | `not_enough_players` | `out_of_cards`.
- `chat_message` — `{player_id, username, text, timestamp}`.
- `you_left_room` — `{room_id}`.

### 2. Контент
- [ ] MinIO в docker-compose с публичным на чтение bucket'ом.
- [ ] Миграция: `meme_cards.image_url` → `image_key`; конфиг `MEDIA_BASE_URL` (и S3-настройки в `.env.example`).
- [ ] Сид-скрипт: загрузка картинок из папки в bucket и запись в БД, плюс тексты ситуаций из файла. Скрипт должен быть идемпотентным.
- [ ] Набрать контент: ≥150 мемов и ≥21 ситуация (см. расчёт ниже), лучше с запасом.
- [ ] Админка для редактирования мемов и ситуаций: просмотр, добавление, изменение, удаление. REST для этого уже есть и закрыт `ADMIN_TOKEN`; нужен интерфейс.

  Чтобы мемов хватило на бесконечную игру при P игроках, нужно `6·P + (P−1)·10` карт: раздача на старте плюс карты, которые лежат на кулдауне, пока не начнут возвращаться. 4 игрока — 54, 6 — 86, 8 — 118, 10 — 150. Меньше — полная комната закончит игру с `out_of_cards`.
  Ситуаций при кулдауне 20 хватает навсегда, если их ≥21; тогда игра заканчивается только по лимиту раундов/очков или владельцем.

### 3. Фронтенд (React)
Экраны определяет состояние с сервера (не в комнате → список комнат, в комнате → лобби, идёт игра → игра), поэтому React Router не нужен; понадобится — например, для ссылок-приглашений — добавим.
- [x] Каркас: Vite + React + TS + Tailwind, ESLint и Prettier; прокси `/api` и `/ws` на бэкенд (`BACKEND_URL`). Перенесены общие компоненты (аватар, шапка, окно стиля) и экран профиля.
- [x] Перенести остальные экраны макета на заглушках: список комнат, лобби, игра (вместе с карточкой мема). Типы данных повторяют протокол (`src/protocol.ts`), заглушки отдаёт `useMockServer` с теми же действиями, что будут у WS-клиента. То, чего нет в правилах сервера, убрано: голосование всех игроков (победителя выбирает ведущий), кнопка «Готов», теги комнат, код комнаты.
- [x] WS-клиент и хранилище состояния (Zustand): токен в `sessionStorage` (у каждой вкладки свой игрок, перезагрузка вкладки сохраняет игрока), автопереподключение с backoff, `send()` с промисом по `request_id`, индикатор соединения. Тесты на Vitest (`npm test`).
- [x] Подключить экраны к серверу: профиль, комнаты, лобби, игра, итоги, чат. Заглушки и инструменты макета удалены; экран выбирается по состоянию (переподключение в комнату сразу возвращает в неё). Дубль вкладки не перехватывает чужого игрока: пока страница открыта, токен хранится только в памяти. Ошибки пока выводятся полоской сверху, выход из идущей игры подтверждается `window.confirm`.
- [x] Ошибки и подтверждения: тосты по `error` с русскими текстами по коду ошибки (`src/api/errorMessages.ts`; тест следит, чтобы у каждого кода из `app/exceptions.py` был текст), диалог подтверждения выхода из идущей игры и завершения игры владельцем.
